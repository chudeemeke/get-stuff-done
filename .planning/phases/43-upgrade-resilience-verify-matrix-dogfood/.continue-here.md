## Anti-patterns (each one bit something this session)

| Do not | Because |
|---|---|
| Run bare `bun test` | A preload guard blocks it. Use `bun run test`, which filters to `.test.js` and routes `.test.cjs` to `test:repository-compat`. |
| Trust an rc or a green-looking log without a summary line | A test file's `process.exit(0)` can end a whole run with rc=0 (issue #45). Read `Ran N tests across M files` and check M. |
| Assert that a config contains a literal you also wrote into it | That is a tautology, not a gate. It is why the verifier's `--from` drifted unnoticed for weeks. Derive expected values from the authority (e.g. the pin in `package.json`). |
| Assume a fix to `scripts/*.js` affects the perf job | It runs a pinned harness checkout, not PR head. |
| Edit files while a gate is running | A green result binds to the tree it ran against. |

## Running the suite (exact)

```bash
bun run test                     # -> scripts/run-bun-tests.js -> bun test .test.js
bun run test:repository-compat   # the .test.cjs contracts, under node --test
```

Never bare `bun test` — a preload guard blocks it.

**Expected:** `Ran 1657 tests across 63 files` — last known green was 1657 pass / 0 fail across
**63 of 63** files, rc=0, on the tree at `da051891`. There are 63 `tests/*.test.js` and 14
`tests/*.test.cjs`. Re-derive rather than trusting this number:

```bash
ls tests/*.test.js | wc -l    # must equal M in "across M files"
```

Checking M is the point: a test file calling `process.exit(0)` can end the whole run with
rc=0 and no summary line at all (issue #45). The suite takes ~9.5 min, over the 10-minute tool
cap, so run it detached writing a terminal marker — **an absent marker means killed, which is
no result, not a failure.**

## Terminology used in these artifacts

- **"CORRECT BUT INERT"** — a fix that is right but cannot take effect where it matters. Used
  for `5b45a921`: the Windows CPU fix is correct, but the perf job runs a pinned harness, not
  PR head. This distinction *is* decision #48.
- **"decisions, not unfinished implementation"** — why red CI here does not mean more coding.
- **"A successful push is not gate evidence"** — the pre-push hook never runs (#49).
- **"A PR's GitHub head is not evidence of current state"** — 86 commits were stranded behind it.
- **"tautology, not a gate"** — a test asserting a config contains a literal you also wrote there.
- **"terminal marker"** — the proof a long run finished; its absence proves it was killed.
- **"paired measurement (base vs head, same runner)"** — why #46 is a real regression, not noise.
- **"trust-boundary change"** — why re-pinning a SHA (#48) is an owner call, not an edit.
