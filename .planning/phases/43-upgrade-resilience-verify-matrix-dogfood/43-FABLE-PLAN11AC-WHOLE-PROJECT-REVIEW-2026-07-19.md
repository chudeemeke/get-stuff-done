## 2. Decisions D1–D8

**D1 — Control vs runtime step.** Adopt the recommended closed exemption: a step is a control step iff it matches the hosted contract byte-exactly on all four dimensions (name, `shell: bash`, env exactly `{GSD_EXPECTED_SUBJECT: <expression>}`, `run` bytes) **and** sits at the contract-mandated position; any deviation stays a runtime step. The exemption is injected from the hosted contract at composition time — single source of truth, no new free-form manifest field. Installing Node/Bun in action-only jobs is rejected. **D1b (defect found in adjudication):** the current rule requires *both* setup-bun and setup-node in any job with a `run` step; live `ci.yml` has nine bun-only jobs, so conformance would force setup-node everywhere — the same mutable-surface defect one level up. Replace the blanket rule with a closed per-job `runtimeRequirements` map (`bun`/`node`/`both`), enforced as an exact set: undeclared run-step job fails, missing declared setup fails, extraneous runtime setup fails. No executable-name guessing is introduced; the closure moves from guess-free blanket to guess-free declaration.

**D2 — Security prelude.** Option 1. harden-runner is only effective before any other step (it monitors subsequent egress including the checkout fetch); checkout-first would structurally weaken the three hardened jobs. Closed rule: step 0 may be exactly one harden-runner step pinned to the manifest SHA with inputs from a closed key/literal allowlist in the contract; then checkout, then adjacent verify. Checkout inputs become a per-job closed allowlist whose only current extra entry is `ci.yml`/Secret Scan → `fetch-depth: 0`; full-history is preserved, `fetch-depth` anywhere else fails. Uniform harden-runner adoption is a Phase 44 candidate, not a Phase 43 requirement.

**D3 — Executed-subject meaning.** Plan 11AC may claim exactly: *"each governed job started from the exact event subject (proven pre-payload), executed a byte-pinned governed step program, with no subsequent checkout and a closed injection surface."* That composition (subject proof + governed workflow-file digests + the existing no-second-checkout rule + D1/D2) is stronger than "momentary HEAD" but is not whole-job worktree immutability, and no product text may imply otherwise. The wrapper/post-payload-receipt path is rejected for Phase 43: later steps legitimately mutate worktrees, an end-of-job `rev-parse` adds little beyond the no-second-checkout rule, and a wrapper is new mutable surface. Stronger attestation, if ever wanted, is Phase 44+ via GitHub-native artifact attestation at the release boundary.

**D4 — Receipts and runner identity.** Rename `full` → `local-runtime` now; `hosted-runtime` is reserved until trusted receipts are actually consumed.
