## Review Output

The revisions close most prior advisory findings without broadly invading
Phase 44. Two blockers remain in the executable plan contract, plus three
high-severity ambiguities that the current RED matrix does not reliably force

### Blockers

#### Trusted Harness Bootstrap And Reachability

The trusted performance harness is neither securely bootstrapped nor fully
reachable by contract.

Evidence:

- Plan 11AH pins measurement to the Fable-accepted 11AG harness checkout.
- The planned `scripts/install-hyperfine.js` belongs to 11AH, not that 11AG
  commit. The plan does not say where the installer executes. Running it from
  the candidate checkout would make untrusted candidate code part of the
  measurement trust root.
- `bench.js` imports `ajv` and the paired domain module, so a bare 11AG checkout
  is not runnable without frozen dependency bootstrap.
- The authorization preflight does not prove the canonical repository can
  resolve the pinned harness/bootstrap SHA.

Minimum correction:

- Introduce a distinct immutable bootstrap authority containing the reviewed
  Hyperfine installer and asset manifest; execute it from a pinned canonical
  checkout, never the candidate.
- Bootstrap harness dependencies in the harness path using frozen,
  script-disabled installation. Never install into the reference or candidate
  checkout, whose cleanliness is required by `bench.js`.
- Add RED cases for candidate-owned installer/bootstrap, missing harness
  installation, wrong working directory, unresolved canonical SHA, and a pin
  that is not the accepted authority.
- Add an event-aware reachability preflight: same-repository heads may prove the
  pin is an ancestor published by the authorized push; fork heads must prove the
  pin is already reachable in the canonical repository.

#### Wrong Verifier For Local Corrective Receipt

Plan 11AJ validates a local corrective receipt with the hosted-envelope
verifier.

Evidence:

- 11AI owns local receipt creation and verification through
  `verify-phase43-corrective-gate.js`.
- 11AJ-00 says it reruns that local gate but verifies the result through
  `verify-hosted-ci.js verify-pending`.
- `verify-pending` validates a hosted envelope with hosted workflows and
  exact-head hosted authority, not a local corrective-gate receipt.

Minimum correction:

- Verify `pre-public-authority.json` with the 11AI corrective-gate verifier.
- Keep `verify-hosted-ci verify-pending` exclusively for the uncommitted
  `post-11n.json` hosted envelope.
- Add cross-type RED fixtures proving each verifier rejects the other receipt
  type. Do not make the hosted verifier polymorphic across local and hosted
  authority.

### High Findings

#### Tier B Transport And Artifact Cardinality

The plan creates 18 Cousin Tier B receipts and three performance receipts, but
explicitly defines only the three paired bundles. It does not determine how the
18 Cousin receipts reach 11AJ.

Minimum correction: encode 18 standalone runtime-receipt artifacts plus three
paired bundles and derive all 21 runtime-bearing artifact identities from the
contract. 11AJ must query and validate all of them.

#### Five Independent Workflow Attempts

"One run attempt" is not defined across five independent workflow runs. GitHub
supplies a separate `(runId, run_attempt)` identity per workflow, while the
current verifier can select the latest attempt independently for each workflow.

Minimum correction: define a hosted cycle as five exact-head workflow runs,
each with its own parent `(runId, attempt)`. Every Tier A, Tier B, and artifact
record matches its own parent. If only the initial automatic cycle is
authorized, require `run_attempt === 1` and reject reruns.

#### Automatic Token Versus Secrets

"No secrets" is too broad. Secret Scan explicitly receives the automatic
GitHub token, and checkout requires a read token even when credentials do not
persist.

Minimum correction: forbid repository, organization, and environment secrets
and token exposure to candidate-controlled run steps. Permit the read-only
automatic token only for an exact allowlist of pinned actions, with
`persist-credentials: false`.
