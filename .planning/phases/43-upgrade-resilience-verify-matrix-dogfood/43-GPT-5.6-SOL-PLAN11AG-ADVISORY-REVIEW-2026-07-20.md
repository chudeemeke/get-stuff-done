## Verdict: ACCEPT_WITH_CORRECTIONS

The paired same-run direction is sound, but the pre-review plan still permitted
ambiguous provenance, trusted derived values, shallow port proliferation, and
legacy waiver influence. The corrections below are implementation blockers.

## First Principles

1. A blocking verdict is a pure function of complete raw same-run samples and
   fixed policy.
2. Provenance describes what executed, not merely what was requested.
3. Stored means, diagnostics, ratios, and verdicts are caches and must be
   recomputed from raw samples.
4. Controls must match; subject package, lock, and upstream-authority digests
   may legitimately differ.
5. Time, historical baselines, accepted regressions, and CLI threshold
   arguments cannot affect paired blocking authority.
6. Measurement authority, hosted workflow authority, and local integration
   confidence are separate claims.

## Blocking Findings And Disposition

### High: Recompute Derived Evidence

The current checker consumes rounded baseline/current means and the current
capture discards raw times. Raw positive durations must become authoritative.
Means, ratios, diagnostics, and verdicts must be recomputed from unrounded raw
values; stored derivative disagreement must fail closed.

**Disposition:** accepted into both Plan 11AG tasks.

### High: Remove Legacy Waiver Authority

The current `acceptedRegressions` path can prevent a ratio above `1.25` from
failing, and the committed baseline contains calendar exceptions.

**Disposition:** paired blocking mode accepts one authority input,
`--comparison`, rejects mixed legacy/threshold arguments, and excludes waiver,
calendar, and baseline-authority fields from its schema. Historical baseline
behavior remains compatibility-only and nonblocking.

### High: Separate Controls From Subjects

The original wording could require equal lock digests even though dependency or
upstream candidates legitimately change their package and lock state.

**Disposition:** shared harness, workload, scheduler, command-template, and
policy digests must match. Each subject separately binds package, lock, and
upstream-authority digests to its exact commit; cross-subject difference is
allowed.

### High: Prove Immutable Execution And Reset

The existing baseline mode runs from project root; install preparation only
deletes `node_modules`, and compose has no reset proof.

**Disposition:** before every sample, paired capture must prove exact full HEAD,
clean worktree, successful preparation, expected controls, and expected subject
digests. Any failure aborts the complete artifact; no pair can be dropped.

### Medium: Use One Deep Port Boundary

Separate execution, timing, validation, comparison, and presentation ports
would create shallow abstractions. Validation and comparison are domain policy;
presentation is already a CLI adapter.

**Disposition:** use `scripts/lib/paired-perf.js` with
`capturePaired(spec, executor)` and `adjudicatePaired(artifact)`. `bench.js`
owns process/filesystem/Hyperfine adapters, `check-perf.js` owns presentation,
and one benchmark-executor port crosses the domain boundary.

### Medium: Separate Comparison Schema Tests

The historical baseline schema test loads only `perf-baseline.schema.json`.

**Disposition:** add `tests/perf-comparison-schema.test.js`; leave historical
baseline schema tests unchanged.

### Medium: Add Semantic Validation

JSON Schema cannot prove contiguous indices, seed-derived alternation, digest
agreement, or recomputed summaries.

**Disposition:** both capture and adjudication must use the closed schema and a
semantic validator.

## Minimum Executor Contract

The executor exposes one environment identity and one complete prepared sample:

```text
identity() -> execution identity
runSample(request) -> {
  executionIdentityDigest,
  resolvedCommit,
  dirty,
  preparationExitCode,
  subjectExitCode,
  durationNs,
  beforeDigests,
  afterDigests
}
```

Requests identify warmup/measured phase, reference/candidate subject, exact
commit/worktree, metric, pair index, order position, command, and preparation.
The outer domain scheduler owns deterministic `AB`/`BA` alternation; the
Hyperfine adapter executes one subject measurement at a time.

## Required Evidence Invariants

- Closed objects and fixed `authority: paired-blocking`.
- Distinct full reference/candidate commits and clean exact-HEAD receipts.
- Complete OS, architecture, CPU, runner image, Node, Bun, and Hyperfine
  identity with one digest referenced by every sample.
- Shared control digests plus separate commit-bound subject digests.
- Exactly `install` and `compose`, with at least ten complete pairs each.
- Contiguous pair indices, seed-derived first order, and exact alternation.
- Equal successful warmups excluded from measured samples.
- Successful preparation and subject exit status for every sample.
- Positive safe-integer nanosecond durations rejected before serialization if
  invalid.
- Candidate arithmetic mean divided by reference arithmetic mean is the sole
  blocking ratio.
- `ratio <= 1.10` passes, `1.10 < ratio <= 1.25` warns, and `ratio > 1.25`
  fails. Any metric failure fails overall; otherwise any warning warns overall.
- Order effect, median, dispersion, per-pair ratio, and absolute delta are
  diagnostics only.
- Stored diagnostics and verdict must match recomputation.
- Capture time and historical baseline data never participate in adjudication.
