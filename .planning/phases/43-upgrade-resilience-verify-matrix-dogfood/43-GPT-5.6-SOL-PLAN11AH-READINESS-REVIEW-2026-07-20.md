### Verdict: REVISE_BEFORE_EXECUTION

11AH is not execution-ready. It depends on 11AG but never explicitly replaces
the absolute baseline with paired authority, cannot represent the necessary
multi-checkout/event model, and lacks the trusted join between paired artifacts,
runtime receipts, and GitHub API evidence.

### Irreducible Truths

- A blocking result must come only from 11AG's paired raw evidence and
  `check-perf --comparison`.
- Reference, candidate, and harness authority each require an immutable
  repository plus 40-hex commit, not a branch, merge ref, or digest asserted by
  the producer.
- PR `github.sha` identifies the synthetic merge commit; PR head authority is
  `pull_request.head.sha`.
- Fork PR code and its artifacts are untrusted. It may run only under
  `pull_request`, on ephemeral hosted runners, without secrets, write
  permissions, persisted credentials, or self-hosted infrastructure.
- Runtime observation and policy expectation must be independent. Equality
  between two values obtained from the same runtime is drift detection, not
  attestation.
- A push-to-main result cannot prevent the push. It is diagnostic evidence, not
  a pre-merge gate.
- Tier A, Tier B, paired evidence, and artifact metadata are separate evidence
  sources. Trust arises from their validated join.
- 11AI local evidence cannot substitute for hosted authority.

### Recommended Event And Subject Model

| Event | Harness | Reference | Candidate | Effect |
| --- | --- | --- | --- | --- |
| PR | Canonical repository at the Fable-accepted immutable 11AG harness commit/digest | `pull_request.base.repo.full_name` at `pull_request.base.sha` | `pull_request.head.repo.full_name` at `pull_request.head.sha` | Blocking paired authority |
| Push to main | Same pinned harness | `github.repository` at `github.event.before` | `github.repository` at `github.sha` | Diagnostic only; skip explicitly when `before` is all-zero or unavailable |
| Schedule/dispatch | Governed workflow bytes at `github.sha` | None for performance | `github.repository` at `github.sha` | No blocking paired verdict |

For PR performance jobs:

- Use three shallow, independent checkout directories: harness, reference, and
  candidate.
- Set exact `repository`, `ref`, `path`, `fetch-depth: 1`, and
  `persist-credentials: false`.
- Verify each checkout's `HEAD` immediately after that checkout.
- Execute `bench.js` and `check-perf.js` from the pinned harness, not the
  candidate checkout.
- Never fetch `refs/pull/*/merge` or use PR `github.sha`.
- Run candidate code only under `pull_request`, `contents: read`, no secrets, no
  write permissions, no cache publication, and no self-hosted runner.

### Runtime And Artifact Authority Flow

```text
event policy + governed harness
  -> verified harness/reference/candidate checkouts
  -> paired comparison + Tier B runtime receipt
  -> immutable artifact upload
Jobs API -> Tier A runner authority
Artifacts API -> artifact ID, archive digest, workflow run/head binding
  -> trusted 11AH join and semantic revalidation
  -> later hosted envelope containing IDs and digests, not copied authority
```

- Tier A owns numeric job ID, job name, runner identity, labels, run ID, and
  attempt.
- Tier B owns observed OS fingerprint, architecture, hosted image name/version
  when available, Node/Bun/Hyperfine versions, and logical runtime subject.
  Local fallback has `hostedImage: null`.
- The paired artifact owns raw samples, two subject SHAs/digests, and 11AG
  controls.
- The 11AH binding owns subject repositories, expected SHAs, governed harness
  digest, Tier A/Tier B/pair file digests, and their equality checks.
- The artifact API supplies artifact ID, archive digest, workflow-run ID, and
  head SHA; these must be collector-bound rather than self-recorded by the
  uploaded bundle.
- Rename the local value to `osFingerprintObserved`; reserve
  `hostedImageName`/`hostedImageVersion` for actual provider image identity.

Hyperfine should be an exact version with OS/architecture-specific immutable
release assets and reviewed SHA-256 values. Record and verify the resolved
version after installation. Mutable apt/Brew/Chocolatey resolution is
insufficient.
